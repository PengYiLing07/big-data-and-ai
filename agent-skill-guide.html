1Skill 是什么？入门
Skill 是打包好的「能力扩展包」，让 AI 遇到特定任务时不必从零摸索，而是读一份自带说明书按流程执行。
一句话

能力扩展包 + 自带说明书

神比喻

给新员工的「实习生上岗手册 / SOP」

解决了什么

AI 不是全知，需要领域专属的「做法」

📎 来源：WorkBuddy 官方文档（能力总览）· workbuddy.cn/docs/workbuddy/Overview ↗
2内部结构长这样入门
技能名/
├── SKILL.md        ✅ 唯一【必填】：说明书 + YAML 元信息
└── 可选资源
    ├── scripts/    可执行代码（跑任务，不占 AI 上下文）
    ├── references/ 长文档（AI「用到才读」）
    └── assets/     产物素材（logo/模板/字体，复制即用）
📎 来源：skill-creator 权威说明书 · workbuddy-builtin/skills/skill-creator/SKILL.md（本机可查看「Anatomy of a Skill」）；也可对照真实技能 expert-manager/ 目录结构
3frontmatter：必填两项入门
---
name: 技能名            ← 必填
description: |          ← 必填：写清「做什么 / 何时用 / 触发词」
  触发场景：……
---

关键：description 决定「何时触发」，写清楚 AI 才会在对的时刻加载它。AI 自建的技能可加一行 agent_created: true 以便后续修改/删除。

📎 来源：skill-creator · 「Metadata Quality / Agent-Created」章节（本机 skill-creator/SKILL.md）；frontmatter 实例见 expert-manager/SKILL.md 顶部
4三级加载（省「脑容量」）进阶
级别内容何时进上下文
1 · 元数据name + description（约百字）始终常驻
2 · SKILL.md 正文流程指引（宜 <5k 词）技能被触发时
3 · 资源scripts / references / assets按需才加载
📎 来源：skill-creator · 「Progressive Disclosure Design Principle」（本机 skill-creator/SKILL.md）
5一次使用怎么流转进阶

扫描 → 触发 → 取用 → 执行 → 沉淀

① 扫描

AI 先比对已装技能列表

② 触发

请求命中某技能 description

③ 取用

读 SKILL.md（必要时读其资源）

④ 执行

照说明书 + 脚本完成任务

⑤ 沉淀

发现可复用方法 → 沉淀成新技能 / 更新旧技能

📎 来源：WorkBuddy 官方文档 · workbuddy.cn/docs ↗（Agent 执行模型）+ 系统级 Agent Skill 加载规范（本会话规则）
6为什么每题都要标「来源」挑战
  • 保证知识可核查：能回链权威出处，而非轻信转述。
  • 利于持续跟进：文档会更新，有链接才能看最新版。
  • 区分「定义性事实」（官方/说明书）与「操作性建议」（实践），学习者知道深浅。
