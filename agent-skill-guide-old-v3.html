① Agent Skill 是什么？

是一个自带说明书的小工具包：由 SKILL.md 说明文档 + 可选的脚本/资料/素材组成。它把"怎么做一件事的专业流程"固化下来，让智能体一读到就能按规范执行。
💡
最贴切比喻：普通智能体像一位聪明的实习生——能力强但没有行业经验；加载 Skill 就像给 TA 一本岗位操作手册 + 工具清单，立刻能按标准干活。

Skill 能提供 4 类能力

🧭
专业流程
多步骤标准做法
🔧
工具集成
特定格式/接口用法
🎓
领域知识
公司规范、业务逻辑
📦
资源捆绑
脚本/模板/素材
🆚
Skill vs 普通对话：普通对话每次都要重新教、易遗漏；Skill 把经验打包复用，写好一次，以后一句话即可触发完整流程。

② Skill 的内部结构

skill-name/
├── SKILL.md   # 必填·总说明书
│   ├── name:        # 技能名
│   └── description: # 何时触发
│       （正文=操作指令）
├── scripts/    # 可选·可执行脚本
│   └── xxx.py
├── references/ # 可选·参考资料
│   └── schema.md
└── assets/    # 可选·输出素材
    └── template.html

必填 SKILL.md —— 技能心脏，含两大部分：

① YAML 头部元数据
必须写 name 和 description。
description 决定"什么任务触发"，用第三人称写清使用时机。
② Markdown 操作指令
告诉智能体"具体怎么做"，用祈使句/动词开头，简洁明确。
💡 三资源何时用？
scripts→确定性执行的代码；references→文档资料用才载入；assets→输出要用的成品文件。

③ 核心机制：三级加载体系 重点

设计目的是省"脑容量"（上下文）——不一次性全塞给智能体，按需调用。

1
元数据（name + description）
始终在上下文中，约 100 词。判断"这技能要不要用"。
总在 · 触发开关
2
SKILL.md 正文
任务触发时才加载（<5000 词），提供核心操作流程。
触发后 · 操作指南
3
捆绑资源（scripts/references/assets）
按需读取；脚本可直接运行不占上下文。
用到才调 · 工具箱
✅ 好处：无关技能不占内存、描述精准触发、复杂资料按需取用 → 反应更快、更省 token。

④ 智能体如何"用"Skill？

扫描触发：面对任务，系统查看所有 Skill 的 name+description 判断匹配。系统提示常说"遇到相关任务第一时间加载本技能"。
调用加载：用 Skill 工具载入匹配的 SKILL.md，正文进入工作上下文。
按需取用资源：需要时读 references，或直接运行 scripts、引用 assets。
规范执行：严格遵循手册流程产出结果。
反思沉淀：做完复杂任务，把可复用流程存成新 Skill；发现旧 Skill 过时就修正（积累与纠错）。

⑤ 快速问答

Q Skill 如何被启用？▾
Skill 是一种能力扩展包，需要时由智能体自动加载使用；通常通过"技能市场 / 对话中安装"获得，属于能力生态的一部分。
Q SKILL.md 为何必须写 description？▾
description 就是技能的"触发开关"——智能体靠它判断当前任务该不该用。写得越精准，越不易误触发或漏触发。
Q 三级加载帮我省了什么？▾
省上下文窗口（"脑容量"）。不会因装了 100 个技能就撑爆上下文——平时只占一行元数据，用到才真正载入。
Q 做完任务为何"沉淀成 Skill"？▾
这是经验积累：把这次摸索的步骤记录下来，下次同类任务直接触发，不用重头研究。也用于反思纠错——发现旧说明有误立即修正。
