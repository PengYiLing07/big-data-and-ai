# Concept Learner — 通用概念学习资料生成引擎

> **设计定位**：本技能不是为某一个概念写死的一段提示词，而是一个**可复用引擎**——给它一个新概念，它按固定心智模型帮你把它学透、学懂、能核查。概念可来自大模型/AI 领域，也可来自任意学科（历史、经济、编程……），只要资料结构和来源纪律成立即可。

## 一、本技能产什么（输出结构固定）

针对**输入概念 X**，产出一份学习资料，正文**必须**依次包含以下 9 个板块（可据此扩展，不可删减核心项）：

1. **🧭 学习目标（Learning Goals）**——学完你应该能回答哪 3~5 个问题。
2. **❓ 核心问题（Core Questions）**——驱动理解 X 的 3~4 个关键问题（如“它解决什么问题”“它由什么组成”“它和相邻概念怎么区分”）。
3. **📖 概念的通俗解释（Plain Explanation）**——用大白话 + 一个生活化类比，把 X 讲给一个零基础的同学听（**用第三人称客观表述，不出现“我/我的”**）。
4. **🎨 可视化图解（Visual Explanation，核心概念 / 难点）**——**用内联 SVG 把不适合纯文字讲清的内容画出来**，至少 2 张图，每张配「读图要点」。选什么画、怎么画，见第 2.5 节。
5. **⚙️ 核心机制 / 组成（Mechanism & Components）**——X 由哪些部分组成、如何运转；尽量用结构图/流程图/表格呈现。
6. **🚀 一个具体应用场景（Concrete Scenario）**——一个真实、可代入的例子，说明 X 怎么被用起来。
7. **⚠️ 易混与边界（Confusions & Boundaries）**——至少 2 条“常被混淆的点”或“X 不能做什么 / 边界在哪”。
8. **🧪 自测问题（Self-check Quiz，可交互）**——**5 道选择题**，按难度分三档（入门 2 题 / 进阶 2 题 / 挑战 1 题）。每题须：① 可点击选择；② 能判分并给出正误反馈；③ 在题下标注**对应知识点与来源**，便于回溯。判分必须可靠：用按钮 `.selected` 显式状态判分（**不要**依赖 `<label>` 内 `<input>` 的 `checked`），答案用 `data-ans` 存、与选项 `data-v` 比对。
9. **🔗 资料来源与可核查链接（Sources）**——列出支撑上述内容的**真实来源**，每条给出可点链接或可查文件路径，不得伪造。

> 结构上建议用 `<h2>` 板块标题 + 目录锚点，方便一屏内扫读。可参考 `assets/learning-template.html`（推荐模板，已内置第 4 板块可视化样式与第 8 板块交互式自测判分脚本，直接复用即可）。

## 二点五、可视化图解板块（第 4 板块）怎么产

### 选什么内容画（判据）

拿到概念 X 后，逐条自问，**命中任意一条就该画**；一个概念通常有 2~4 个这样的点，挑最重要的 2~3 个成图：

| 内容类型 | 该不该画 | 建议图形 |
|---|---|---|
| 组成部分 / 内部结构（“由什么构成”） | ✅ 强烈建议 | 结构图：外层容器 + 内部模块，或分层方块 |
| 层次 / 分级 / 递进（如三级披露、金字塔） | ✅ 强烈建议 | 阶梯图、同心圆、金字塔 |
| 多步流程 / 循环（感知→推理→行动） | ✅ 强烈建议 | 横向流程图、带返回箭头的闭环 |
| 易混概念的对比（A vs B） | ✅ 强烈建议 | 左右对照双栏，用颜色区分 |
| 量的对比 / 边界（窗口大小、性能取舍） | ✅ 建议 | 条形对比、刻度尺、天平隐喻 |
| 抽象机制的空间关系（注意力、漏斗、管道） | ✅ 建议 | 示意性隐喻图（简化剖视 / 空间比喻） |
| 纯定义、一句话能说清的事实 | ❌ 不画 | 文字即可 |
| 需要精确数值表、长清单 | ❌ 不画 | 用表格 |
| 时间顺序的历史事件（>5 个节点） | ⚠️ 谨慎 | 优先用文字时间线，避免图过密 |

### 怎么画（硬性规范）

- **技术形态**：内联 `<svg>`，`viewBox="0 0 W H"`，`width="100%"`，**自包含、无外部依赖**（不引 CDN、不用外部图片），保证离线双击可看。
- **配色**：与模板一致——主色 `#2f6fed`，成功/正向 `#1a9e5a`，警示/难点 `#d97706`，对比色可用 `#7c5cff`；同类元素同色，**颜色只用来编码含义，不做装饰**。
- **文字**：字号不小于 11px；每个图形元素都要有标签，不能让读者猜；标题写在图上方（用 `.vcap`），不要在 SVG 里放大段说明。
- **每张图必须三件套**：① 图题 `.vcap`；② 一句 `.vsub` 副标题说明这张图在讲什么；③ 图下 `.viz-note`「🎯 读图要点」——用一句话点出这张图最该记住的结论。
- **无障碍**：`<svg>` 加 `role="img"`，首个子元素为 `<title>`（图名）与 `<desc>`（一句话描述图意）。
- **数量纪律**：**至少 2 张，最多 3 张**。宁少勿滥——每张图都要能回答一个具体问题，不为凑数画图。
- **不确定时不画**：若某机制自己也没把握画准，宁可改用表格或文字，**不得画一张会误导读者的图**；可在 `.viz-note` 中注明“示意图，仅帮助理解，非精确结构”。

### 图后自检

- [ ] 遮住正文只看图，能否说出这张图想表达什么？（不能则重画）
- [ ] 图中每个色块 / 箭头都有标签或图例吗？
- [ ] 图与正文结论一致，没有为好看而简化到失真？
- [ ] 去掉 CSS/JS 后，图仍能正常显示吗？（纯 SVG 应可）

## 三、输入信息（调用时你需拿到什么）

- **必填**：待学习的概念名 X（例如 “Agent”）。
- **可选**：学科/背景（默认 AI/大模型领域，若未给按通用处理）；希望资料存为 .html 还是 .md（默认 .html）；目标篇幅（默认“一分钟扫读 + 可深入”的适中长度）。
- 若用户一次给了多个概念，**一次只聚焦一个**生成一份；多份请分多次调用或明确说明逐一生成。

## 三、生成步骤（Workflow）

1. **澄清输入**：若 X 不明（同义词/多义），先向用户确认指向（如 “Agent 指 AI 智能体还是别的？”）。
2. **联网/本地核查来源（关键，禁止编造）**：
   - 用网络搜索/文档抓取核实 X 的定义与关键机制；优先官方文档、学术教材、权威教程、可信技术博客。
   - 只采用**能定位到真实出处**的表述；拿不准的知识要么核实要么标注“个人理解，待核”。
   - 把采用的来源与链接记录下来，供第 9 板块引用。
3. **组织框架**：按第一节的 9 板块把素材组织成文。先写通俗解释与类比（用大白话，不全篇照抄资料），再判断「哪些内容该画图」并产出第 4 板块的可视化图解，接着搭机制表、场景、辨析，最后按三档难度出 5 道自测题并标注来源。
4. **落盘**：把成果写成 HTML（推荐，用模板）或 Markdown，存到 `learning-materials/`（见第六节），文件命名见下。
5. **自检（Self-check）**：对照第四节逐条检查通过后再交付。
6. **向用户说明**：资料里哪些是**权威来源结论**、哪些是**辅助理解/图示概括**，便于老师区分“核查内容”与“辅助说明”。

## 四、自检要求（交付前必过）

- [ ] **结构完整**：9 个板块齐全（含第 4 板块「可视化图解」与第 8 板块「自测问题」），无缺项。
- [ ] **可视化达标**：第 4 板块至少 2 张内联 SVG 图，每张有图题、副标题与「读图要点」；`<svg>` 含 `role="img"` + `<title>` + `<desc>`；无外部依赖、离线可显示；图示与正文结论一致。
- [ ] **自测可用**：5 道选择题可点击作答、能正确判分（选中项与 `data-ans` 比对）；每题标注来源；答案存在于选项中；**交付前先自测判分逻辑**（选对应得满分、选错应判错）。
- [ ] **人称统一**：全文**不得出现“我 / 我的 / 我们”等第一人称**；类比与核查块统一用「💡 一个类比」「✅ 核查说明（人工）」，综合整理处用“本页/综合多来源整理”表述。
- [ ] **来源可核查**：每个关键论断能指向真实来源；链接格式正确、非占位；无凭空捏造的 URL。
- [ ] **概念准确**：通俗解释与权威定义方向一致，无严重错漏；机制部分与主流资料吻合。
- [ ] **辅助理解在场**：有类比、有通俗化说明，不是整段照搬 AI 输出；与课堂/学习经验有勾连。
- [ ] **边界充分**：至少 2 条易混/边界说明。
- [ ] **文件落位正确**：放在 `learning-materials/<概念>.html`（命名见下）。
- [ ] **安全**：正文不含任何 API Key、密码、个人隐私或敏感信息。

## 五、工程与命名约定

- 默认产出**自包含 HTML**（CSS/JS 内联，可离线双击打开），文件名小写连字符：
  - `learning-materials/agent.html`
  - `learning-materials/llm-context.html`
  - `learning-materials/skill.html`
- 若产出 Markdown，命名同理：`learning-materials/<concept>.md`。
- 页面顶部标注“由 concept-learner 生成 + 版本/日期”，便于可追溯、可核查。

## 六、产物落盘约定（项目级使用）

- **项目级 Skill** 位于仓库 `.workbuddy/skills/concept-learner/`，在本仓库调用时，生成的资料统一保存到仓库根目录的 **`learning-materials/`** 文件夹。
- 若要学的新概念在历史上已生成过，先检查 `learning-materials/` 是否已有同名文件：已有则提示“是否覆盖/补充”，避免静默覆盖。

## 资源
- `references/source-policy.md` —— 资料来源纪律：如何判定可信来源、如何避免伪造链接、如何区分“权威结论”与“个人理解”（本仓库三份资料的来源即遵守此规范）。
- `assets/learning-template.html` —— 推荐的学习资料 HTML 模板（含 9 板块骨架、目录锚点、来源引用样式、第 4 板块可视化样式，以及第 8 板块的交互式自测与判分脚本）。
