# Concept Learner — 通用概念学习资料生成引擎

> **设计定位**：本技能不是为某一个概念写死的一段提示词，而是一个**可复用引擎**——给它一个新概念，它按固定心智模型帮你把它学透、学懂、能核查。概念可来自大模型/AI 领域，也可来自任意学科（历史、经济、编程……），只要资料结构和来源纪律成立即可。

## 一、本技能产什么（输出结构固定）

针对**输入概念 X**，产出一份学习资料，正文**必须**依次包含以下 8 个板块（可据此扩展，不可删减核心项）：

1. **🧭 学习目标（Learning Goals）**——学完你应该能回答哪 3~5 个问题。
2. **❓ 核心问题（Core Questions）**——驱动理解 X 的 3~4 个关键问题（如“它解决什么问题”“它由什么组成”“它和相邻概念怎么区分”）。
3. **📖 概念的个人解释（Plain Explanation）**——用你自己的话 + 一个生活化类比，把 X 讲给一个零基础的同学听。
4. **⚙️ 核心机制 / 组成（Mechanism & Components）**——X 由哪些部分组成、如何运转；尽量用结构图/流程图/表格呈现。
5. **🚀 一个具体应用场景（Concrete Scenario）**——一个真实、可代入的例子，说明 X 怎么被用起来。
6. **⚠️ 易混与边界（Confusions & Boundaries）**——至少 2 条“常被混淆的点”或“X 不能做什么 / 边界在哪”。
7. **🧪 自测问题（Self-check Quiz，可交互）**——**5 道选择题**，按难度分三档（入门 2 题 / 进阶 2 题 / 挑战 1 题）。每题须：① 可点击选择；② 能判分并给出正误反馈；③ 在题下标注**对应知识点与来源**，便于回溯。判分必须可靠：用按钮 `.selected` 显式状态判分（**不要**依赖 `<label>` 内 `<input>` 的 `checked`），答案用 `data-ans` 存、与选项 `data-v` 比对。
8. **🔗 资料来源与可核查链接（Sources）**——列出支撑上述内容的**真实来源**，每条给出可点链接或可查文件路径，不得伪造。

> 结构上建议用 `<h2>` 板块标题 + 目录锚点，方便一屏内扫读。可参考 `assets/learning-template.html`（推荐模板，已内置第 7 板块的交互式自测与判分脚本，直接复用即可）。

## 二、输入信息（调用时你需拿到什么）

- **必填**：待学习的概念名 X（例如 “Agent”）。
- **可选**：学科/背景（默认 AI/大模型领域，若未给按通用处理）；希望资料存为 .html 还是 .md（默认 .html）；目标篇幅（默认“一分钟扫读 + 可深入”的适中长度）。
- 若用户一次给了多个概念，**一次只聚焦一个**生成一份；多份请分多次调用或明确说明逐一生成。

## 三、生成步骤（Workflow）

1. **澄清输入**：若 X 不明（同义词/多义），先向用户确认指向（如 “Agent 指 AI 智能体还是别的？”）。
2. **联网/本地核查来源（关键，禁止编造）**：
   - 用网络搜索/文档抓取核实 X 的定义与关键机制；优先官方文档、学术教材、权威教程、可信技术博客。
   - 只采用**能定位到真实出处**的表述；拿不准的知识要么核实要么标注“个人理解，待核”。
   - 把采用的来源与链接记录下来，供第 8 板块引用。
3. **组织框架**：按第一节的 8 板块把素材组织成文。先写个人解释与类比（用自己的话，不全篇照抄资料），再搭机制图、场景、辨析，最后按三档难度出 5 道自测题并标注来源。
4. **落盘**：把成果写成 HTML（推荐，用模板）或 Markdown，存到 `learning-materials/`（见第六节），文件命名见下。
5. **自检（Self-check）**：对照第四节逐条检查通过后再交付。
6. **向用户说明**：资料里哪些是**权威来源结论**、哪些是**你的个人理解/类比**，便于老师区分“核查内容”与“个人判断”。

## 四、自检要求（交付前必过）

- [ ] **结构完整**：8 个板块齐全（含第 7 板块「自测问题」），无缺项。
- [ ] **自测可用**：5 道选择题可点击作答、能正确判分（选中项与 `data-ans` 比对）；每题标注来源；答案存在于选项中；**交付前先自测判分逻辑**（选对应得满分、选错应判错）。
- [ ] **来源可核查**：每个关键论断能指向真实来源；链接格式正确、非占位；无凭空捏造的 URL。
- [ ] **概念准确**：个人解释与权威定义方向一致，无严重错漏；机制部分与主流资料吻合。
- [ ] **个人在场**：有类比、有“我的理解”句式，不是整段照搬 AI 输出；与课堂/个人经验有勾连。
- [ ] **边界充分**：至少 2 条易混/边界说明。
- [ ] **文件落位正确**：放在 `learning-materials/<概念>.html`（命名见下）。
- [ ] **安全**：正文不含任何 API Key、密码、个人隐私或敏感信息。

## 五、工程与命名约定

- 默认产出**自包含 HTML**（CSS/JS 内联，可离线双击打开），文件名小写连字符：
  - `learning-materials/agent.html`
  - `learning-materials/llm-context.html`
  - `learning-materials/skill.html`
- 若产出 Markdown，命名同理：`learning-materials/<concept>.md`。
- 页面顶部标注“由 concept-learner 生成 + 版本/日期”，便于可追溯、可核查。

## 六、产物落盘约定（项目级使用）

- **项目级 Skill** 位于仓库 `.workbuddy/skills/concept-learner/`，在本仓库调用时，生成的资料统一保存到仓库根目录的 **`learning-materials/`** 文件夹。
- 若要学的新概念在历史上已生成过，先检查 `learning-materials/` 是否已有同名文件：已有则提示“是否覆盖/补充”，避免静默覆盖。

## 资源
- `references/source-policy.md` —— 资料来源纪律：如何判定可信来源、如何避免伪造链接、如何区分“权威结论”与“个人理解”（本仓库三份资料的来源即遵守此规范）。
- `assets/learning-template.html` —— 推荐的学习资料 HTML 模板（含 8 板块骨架、目录锚点、来源引用样式，以及第 7 板块的交互式自测与判分脚本）。
