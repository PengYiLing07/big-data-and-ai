📚 概念关系说明 · concept-learner 配套文档

Agent、大模型的上下文、Skill —— 三者的关系

课程：大数据与人工智能

🧩 一、一句话总览

这三个概念不是三个孤立名词，而是同一条工作链上的三个环节： 上下文（Context）是 Agent 的「视野与工作记忆」， Agent 是在这份上下文上反复「想 → 做 → 看」的执行体， 而 Skill 是把「怎么处理一类任务」的方法，提前沉淀成可复用的说明书，让 Agent 在有限上下文里更聪明、更省地干活。

🔗 二、逐对关系

关系说明
上下文 → Agent
（视野决定表现）		 Agent 每一轮决策都只基于「当前上下文窗口里有什么」。上下文给了它：它是谁（系统提示）、对话到哪了（历史）、刚查回什么（工具结果）。
关键：上下文越相关、越无噪声，Agent 判断越准；上下文被撑爆或关键信息被挤掉，Agent 就会“忘事/跑偏”。所以 Agent 的能力上限，很大程度取决于它能否高效利用有限的上下文。
上下文 ← Skill
（Skill 改变“进什么上下文”）		 Skill 平时不进上下文（只有 name+description 占极小空间）；一旦被触发，它才把「怎么做这类任务」的正文、参考、脚本读进窗口。
作用：让 Agent 在不预先占满上下文的前提下，需要时立刻获得专业流程知识。Skill 其实是「上下文内容的生产者和节流阀」——按需注入、用完即走。
Agent ← Skill
（Skill 增强 Agent）		 Skill 让同一个通用 Agent 能“临时变身”成专家：处理 PDF、写报表、做数据分析……本质是给 Agent 追加可复用的行为包。它也反过来体现了「沉淀」——把做过一遍的有效方法固化，下次不用重新摸索。

⚙️ 三、上下文如何影响 Agent 的工作（重点）

  • 决定“它知道什么”：上下文里放的系统提示定义了 Agent 的角色与边界；放的知识/参考决定了它答题的依据范围。
  • 决定“它记得什么”：多轮任务里，历史对话让 Agent 记住用户偏好与已做步骤；上下文越长，越考验管理能力（超限会用摘要/检索保住关键）。
  • 决定“它怎么执行”：Agent 决定调用哪个工具、如何组织下一步，都依据窗口里此刻的信息与工具定义。噪声太多会干扰判断（丢了西瓜捡芝麻）。
💡 一句话 上下文是 Agent 的「工作台」，Agent 的所有聪明都建立在「工作台上此刻摆了什么」之上——摆得好，它就高效；摆得乱或摆不下，它就出错。

📦 四、Skill 如何沉淀可复用的任务知识

Skill 是「把经验固化成资产」的载体，价值在三个层面：

层面做法收益
复用把做过一遍的有效流程写成 SKILL.md（怎么做、注意什么、调什么脚本）。下次同类任务直接调用，不再重复贴长提示词，也不易遗漏步骤。
共享项目级 Skill 放进仓库技能目录，随 git 提交。团队或未来的自己，克隆仓库即获得同一套方法，学习成果统一落盘。
省上下文靠渐进式披露：平时只占元数据，需要时才载入详细内容。可同时携带大量技能而不挤爆上下文，反而让 Agent 更“专业”。

本仓库就是一个实例：concept-learner Skill 把「如何学懂并核查任意概念」的方法沉淀下来，并由此产出 agent / llm-context / skill 三份资料——方法存进 Skill，成果放进 learning-materials/，正是“沉淀”的体现。

🔄 五、它们如何串成一条工作流

你：“帮我搞懂 Agent 这个概念” ↓ 命中 concept-learner 的 description Skill 触发 → 把“如何产出概念资料”的方法读进 上下文 ↓ Agent 在这个上下文上：想(规划 7 板块) → 做(联网核查来源) → 看(对照自检) ↓ 写出 agent.html，落盘 learning-materials/ ↓ 人工核查 → 修改 → commit & push（GitHub 沉淀） 下次学任何新概念，同一套 Skill + 上下文 → Agent 自动复用

这条链正好说明：上下文提供“此刻该知道什么”，Agent负责“据此把事办成”，Skill保证“办这类事的方法被反复用好、沉淀下来”。三者环环相扣。

👤 六、理解与核查

✅ 综合判断 + 人工核查记录 三者可概括为「容器 / 执行者 / 方法库」的关系：上下文是容器（有限的视野），Agent 是执行者（在视野内推理行动），Skill 是方法库（把流程知识按需注入容器）。 “上下文影响 Agent”——从 Agent 组件资料与上下文工程资料交叉印证：Agent 每轮决策只依赖窗口内信息，窗口质量直接决定表现，该结论经多来源印证后采信并特别强调。 “Skill 沉淀任务知识”——依据 Anthropic 官方文档对渐进式披露与可复用性的描述。 关系图与“容器/执行者/方法库”比喻属于帮助理解的概括，不是某来源原文。
