🧭 一、学习目标

📌 本页的定位 本页面向的是「能读懂别人写的代码」，而不是「从零设计一个类」。目标是：翻到任何一份第三方库文档或示例代码，能看出哪一行在创建对象、哪一行在调用方法、括号里的东西对应文档中的哪张参数表，从而照着文档改参数、把示例跑通。因此本页不展开特殊方法重载、元类、抽象基类等设计话题。

学完本页后，读者应该能够回答：

  • 类和实例是什么关系？为什么说「类是模具，实例是产品」？

  • 类属性与实例属性有什么区别？为什么有时改一个实例的属性能影响另一个实例、有时又不会？

📖 三、概念的通俗解释

📌 阅读范围提示 这一节的读法建议是：把重点放在「怎么读」而不是「怎么写」。下面出现的每一段代码，都要能回答两个问题——哪一部分是「一只模具」，哪一部分是「用这只模具造出来的东西」；哪些名字挂在模具上，哪些名字挂在具体产品上。这两问能答上来，第三方库的文档就读得动了。

Python 官方教程《类》的开篇说明：类把数据与功能打包在一起，创建新类就是创建一种新的对象类型，从而可以创建该类型的实例。类定义本身不产生任何数据，它只是一份说明；真正持有数据的是实例。

一份典型的类定义包含两种成员。属性负责存数据，例如一条评论记录会有「来源」「字数」「标签」；方法负责做事，例如「算不算长评论」「生成一行摘要」。方法定义在类里，但它的第一个参数总是 self——官方教程把它解释为指向调用该方法的那一个实例本身，由 Python 在调用时自动传入，因此写代码时不需要（也不应该）手动填。

__init__ 是一个特殊名字的方法，在创建实例的那一刻自动被调用，用来给这个新实例挂上初始属性。因此 Comment("A 报", 86) 这样的写法会先造出一个空实例，再立刻执行 __init__，把参数写进实例自己的属性里。这也是为什么「创建对象」这一步在括号里可以填参数——那些参数实际上是传给 __init__ 的。

最后是「为什么要懂这个」。以机器学习库 scikit-learn 为例，官方《Getting Started》给出的用法是：先 clf = RandomForestClassifier(random_state=0) 创建一个估计器对象，再 clf.fit(X, y) 用数据拟合它，之后 clf.predict(X) 直接对同一对象调用预测方法——文档明确说明「一旦估计器完成拟合，就可以用于预测新数据的目标值，不需要重新训练」。也就是说，训练得到的中间结果保存在对象内部，靠的就是「对象既能存数据、又能提供方法」这一条。看清这一点，绝大多数 AI 库的示例代码都能读通了。

💡 一个类比 类可类比为一只模具或一张图纸，实例可类比为按这只模具做出来的具体产品：模具只有一副，产品可以有很多件；每件产品身上刻的字（属性值）可以各不相同，但形状与可做的动作（方法）都由模具决定。这一类比属于帮助理解的通俗化说法，非官方原文。
💡 一个类比 self 可类比为「当前这件产品指的是它自己」：写「把重量记到自己的属性上」时，这句话对每一件产品都成立，因此不必逐一写死。model.fit(X, y) 这类调用，相当于对某一件具体的产品下令「用这批数据训练你自己」。这一类比属于帮助理解的通俗化说法，非官方原文。

⚙️ 五、核心机制 / 组成

一个类通常由下面这些成员组成。读懂第三方库文档时，只需要抓住「哪些名字属于类、哪些属于实例」这一条线索。

组成部分作用 / 说明读代码时的识别要点
类 class一种自定义类型的说明，规定该类实例拥有哪些属性、能做哪些动作。类定义本身不产生具体数据。看到 class 名字: 即开始一份说明
实例按类创建出来的具体对象，真正持有数据。同一个类可以创建任意多个实例。看到 名字 = 类名(参数) 即在创建实例
__init__创建实例时自动调用的初始化方法，用于给新实例挂上初始属性。它不是「手动调用的构造函数」。看到类名括号里有参数，说明参数传给了 __init__
实例属性挂在某一个实例上的数据，通常写作 self.属性名 = 值。各实例之间互不影响。读法：对象.属性名
方法定义在类里的函数，第一个参数通常命名为 self，由 Python 在调用时自动传入，指向调用该方法的那一个实例。读法：对象.方法名(参数)，调用时不用写 self
类属性直接写在类里（不在 __init__ 里）的变量，所有实例默认共享同一个值。注意：通过某个实例对它赋值，会在该实例上新建一个同名实例属性
继承在类名后写父类名，使新类自动获得父类的属性与方法，并可覆盖其中一部分。看到 class 子类(父类):
super()在内置函数文档中给出用法：super().method(arg) 等价于 super(类, self).method(arg)，用于在子类中调用父类的实现。常见于子类的 __init__ 第一行
__str__ / __repr__官方《数据模型》3.3.1 节说明：__repr__ 由内置函数 repr() 调用，输出偏「官方」的表示，主要用于调试；__str__ 由 str()、print() 与默认的 __format__() 调用，输出适合阅读的表示。若只定义了 __repr__，__str__ 也会用它。决定 print(对象) 打印出什么

🚀 一个具体应用场景

编辑部希望用「评论字数」与「是否含链接」两个特征，给评论的正面 / 负面倾向做一个最简的自动判别。文档里给出的是一段对象式调用的示例代码；照着文档改参数、把它跑通，就是这个场景要完成的事。 

# 场景：读懂第三方库文档里的对象式调用，照着文档改参数跑通示例
import numpy as np
from sklearn.linear_model import LogisticRegression

# ① 创建对象：括号里的内容对应文档 Parameters 表
model = LogisticRegression()

# ② 准备数据：X 每行一条评论（字数、是否含链接），y 是对应的标签
X = np.array([[86, 0], [42, 1], [25, 0], [120, 1], [15, 0], [95, 1]])
y = np.array(["正面", "负面", "负面", "正面", "负面", "正面"])

# ③ 调用方法：fit 用数据拟合；结果保存在 model 这个对象内部
model.fit(X, y)

# ④ 调用同一对象的另一个方法：不需要重新训练，直接预测新数据
print(model.predict([[70, 0], [30, 1]]))

# ⑤ 读取属性：属性和方法一样，都用「对象.名字」的写法
print(model.classes_)   # 模型认识的类别标签

这一段是文章级别的示例，用于说明「创建对象 → 调用方法」这一句式，属于辅助理解示例，非某个来源的原文代码。其中「先创建估计器、再调 fit、之后可直接 predict 而无需重新训练」的流程与「classes_ 属于拟合后才有的属性」两点，依据 scikit-learn 官方《Getting Started》与 LogisticRegression 参考页。

✅ 核查说明（人工） 上述示例只演示调用形式，不涉及模型效果的评估。真实任务中，样本量、标签来源、特征选择都会显著影响结果，本节不对其预测质量作任何判断。

⚠️ 易混与边界

  • 「读懂对象」与「从零设计类」是两件事。本页的定位是前者。做 AI 应用时，绝大多数对象来自第三方库，使用者的工作是「按文档填参数、按顺序调用方法」，而不是决定类该怎么设计。常见误解是「不懂面向对象就没法用 AI 库」——实际情况恰好相反：只要抓住「创建对象 → 调用方法」这一句式，示例代码就能跑通。
  • 类属性与实例属性容易混。直接写在类里的变量是类属性，所有实例默认共享同一个值；写在 __init__ 里、以 self.属性名 形式赋值的才是实例属性。需要留意的情形是：通过某个实例给一个类属性赋值，Python 会在该实例上新建一个同名实例属性，此后这个实例读到的就是自己的值，其他实例与类本身都不受影响——这会造成「看起来只改了 a，结果 a 和 b 表现不同」的困惑。
  • __init__ 不是「构造函数」，也不应手动调用。它在创建实例时由 Python 自动执行。常见误解是「必须自己写一行 obj.__init__() 才算初始化完成」——手动调用通常会导致重复初始化，甚至覆盖已有属性。
  • self 不出现在调用处。方法定义里第一个参数是 self，但调用时写成 obj.method(x)，不需要、也不应写成 obj.method(obj, x)。self 的名字只是惯例（官方教程也说明它只是一个普通参数名，虽可改成别的名字但会降低可读性），真正起作用的是「它是第一个参数」这个位置。
  • 属性不一定在创建时就存在。scikit-learn 的术语表说明：在 fit 中设置的公共属性以单个下划线结尾（如 coef_、classes_），而它们只在拟合之后才存在；术语表还注明，未拟合的估计器不应拥有这类属性。因此直接读取 model.coef_ 之前，要先确认已经调用过 fit。
  • 能读懂≠能改对。第三方库的对象内部通常有大量约定（例如 predict 要求输入的特征顺序与 fit 时一致）。读懂调用形式只解决了「怎么用」，特征是否对齐、标签是否可靠，属于数据层面的事，文本层面的「能读通代码」在这里并不构成质量的保证。
