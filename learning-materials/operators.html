📖 三、概念的通俗解释

运算符是告诉 Python「拿这几个值做什么」的符号。 被运算符作用的值叫操作数。把运算符和操作数组合起来，就构成一个表达式——表达式会被求值，求出一个结果。 例如 len(body) - 200 里，len(body) 与 200 是操作数，- 是运算符，整个式子的求值结果是两者之差。

单靠变量只能「存」数据：把标题存进 title、把字数存进 chars。真正让程序产生价值的是「算」和「判断」，而这两件事全部由运算符承担—— 算字数、算比例、算阅读时长靠算术运算符；判断稿件是否超长、标题是否命中关键词靠比较、成员与逻辑运算符。 可以说，程序里的每一个决策，最后都落在一个表达式上。

需要留意一个容易忽略的区分：表达式会求出值，而赋值不是一个表达式。 x = 5 是一条赋值语句，它把名字 x 绑定到对象 5，本身并不产出可以继续参与运算的值——这也是 Python 里 if (x = 5): 这种写法直接报语法错误的原因。

💡 一个类比 运算符可类比为稿件流转中的一批标准工序标记：有的标记表示「算出这个数」，有的表示「判断是否达标」，有的表示「把结果登记到某个名目下」。 工序标记本身不产出内容，它决定的是这批内容按什么规则被加工。同一批内容配上不同标记，得到的结果可以完全不同——这正是「同样的数据，写错一个符号结果就变味」的由来。

补充说明：上面这段类比属于辅助理解，不是 Python 官方文档的定义。官方文档是按「运算符优先级 + 各类运算符的语义」分别成文描述的，见本页第九节来源。

⚙️ 五、核心机制 / 组成

Python 的运算符按「用途」分成若干家族。下表按家族列出符号、产出结果与新闻场景中的典型用途——先看清「产出什么」，再决定把它放在哪里用。

家族符号产出结果新闻场景中的用途
算术 + - * / // % ** 数字；+ 与 * 作用于序列时得序列 统计字数、算比例、分秒换算、按段落数切分
赋值 = += -= *= /= //= %= **= 不产出可用作表达式的值（是语句） 累加计数、把清洗后的结果写回变量名
比较 == != < <= > >= True / False；可串连成 a < b < c 判断稿件是否超长、某段是否比平均长度更长
逻辑 and or not 返回最后被求值的操作数；只有 not 一定返回布尔值 多条推送门槛同时满足、给空值兜一个默认值
成员 in not in True / False 标题里有没有某个关键词、某标签是否在标签表里
身份 is is not True / False 判断某个字段是否为 None（尚未填写）

运算是怎么一步步被确定的

一个表达式被求值时，Python 按固定顺序处理，机制可以拆成四步：

环节说明
1. 确定操作数先把每个操作数求值出来（例如 len(body) 先算出字数），赋值的右侧先于左侧求值。
2. 按优先级分组根据优先级决定哪两个操作数先结合。同级运算符除 ** 与条件表达式外，都从左至右结合。
3. 查类型的运算规则同一个符号在不同类型上行为不同：+ 对数字是加法，对字符串是拼接；* 对一个整数与一个序列是重复。
4. 产出结果算术得数字，比较 / 成员 / 身份得布尔值，逻辑得操作数本身，赋值则把结果绑定到名字。

优先级速查（由高到低）

层级运算符说明
1**幂，绑定最紧；且高于其右侧的一元运算符
2+x -x ~x一元正负号、按位取反
3* / // %乘、除、整除、取余（矩阵乘 @ 同层，内置类型未实现）
4+ -加、减
5<< >> & ^ |移位与按位运算，夹在加减与比较之间；本课不展开
6in not in is is not < <= > >= != ==比较、成员、身份同为一级，遵循从左至右的串连特性
7not逻辑非
8and → or逻辑与高于逻辑或
9a if cond else b条件表达式，优先级最低

结合性补充：同一层级的运算符通常从左至右结合，只有幂运算符与条件表达式是从右至左。因此 2 ** 3 ** 2 等价于 2 ** (3 ** 2)，结果为 512，而不是 (2 ** 3) ** 2 的 64。

🚀 六、一个具体应用场景

场景是新闻编辑室的一个常见动作：稿件拟推送前，先算出阅读时长，并检查是否满足几条门槛。 这件事用一个脚本就能完成，而它几乎把本页六类运算符全用了一遍——算术算时长、赋值存结果、比较比长度、成员查关键词、逻辑做综合判断。 

# 场景：稿件发出前，一把算出「阅读时长」并判断是否符合推送要求
title = "老旧小区改造调查：三个小区的账本"
body = "记者近日走访了城东、城西与城南三个老旧小区。\n" * 40

# 1) 去掉空白，得到有效字数（字符串的 replace 与 len）
chars = len(body.replace(" ", "").replace("\n", ""))

# 2) 中文阅读速度按每分钟 300 字估算（示例参数，可按栏目调整）
total_seconds = chars * 60 // 300      # // 向下取整，先得到整秒
minutes = total_seconds // 60          # 再换算成整分钟
seconds = total_seconds % 60           # % 取余，得到剩余秒数
print(f"《{title}》共 {chars} 字，约 {minutes} 分 {seconds} 秒")

# 3) 三条推送门槛，用逻辑运算组合起来
short_enough = chars <= 900                             # 篇幅够短
has_topic = ("改造" in title) or ("调查" in title)       # 命中选题关键词
not_breaking = title != ""                              # 标题非空
ready = short_enough and has_topic and not_breaking
print("可推送" if ready else "需人工复核")

# 4) 顺带看一眼：and / or 返回的是操作数本身，而不是 True / False
print(chars and "字数非零", repr(title or "未命名"))

# 5) 自检：用 // 与 % 拼回去，应该正好等于原值
print("校验通过" if minutes * 60 + seconds == total_seconds else "校验失败")

以上代码在本地 Python 3.12.10 解释器（.venv\Scripts\python.exe）实跑，输出如下：

《老旧小区改造调查：三个小区的账本》共 880 字，约 2 分 56 秒
可推送
字数非零 '老旧小区改造调查：三个小区的账本'
校验通过

这段代码里值得单独记住的三点

写法它在做什么
chars * 60 // 300先乘后整除。// 的作用是「向下取整得到整秒」，如果写成 /，得到的是 176.0 这样的浮点数，后面做「几分几秒」的展示就得额外处理。
total_seconds // 60 与 total_seconds % 60这是把总量拆成「整份 + 余数」的标准套路：// 拿整份（整分钟），% 拿余数（剩余秒数）。凡是「几小时几分钟」「几页几行」这类换算都用它。
chars <= 900 and ... or ...多个条件用 and 串起来，任一不满足 ready 即为假；关键词命中用 or，只要命中一个就算通过。条件一多，建议按本例拆成几个有名字的变量，比堆在一行更易读。
✅ 核查说明（人工） 本页所有反直觉示例均在本地 Python 3.12.10 中实跑核对，与官方文档描述一致：-7 // 2 得 -4、-7 % 2 得 1、7 % -2 得 -1、-3 ** 2 得 -9、4 / 2 得 2.0、1 and 2 得 2、0.1 + 0.2 == 0.3 得 False。另有两点来自实跑观察：1 is 1.0 得 False（值相等不等于同一对象），且解释器会就此发出 SyntaxWarning 提示，说明用 is 比较数字字面量本身就不是推荐写法。

⚠️ 七、易混与边界

  • = 与 == 是两件事。= 是赋值语句，== 是比较运算。把 == 少写一个等号通常不会立刻报错，而是静默改变程序行为——这是最难排查的一类错误，因为程序照常运行，只是判断结果反了。
  • is 不能替代 ==，反之亦然。== 比较值，is 比较是否为同一个对象。官方教程的例子说明得很清楚：1 == 1.0 为 True，而这两个值并非同一个对象。PEP 8 给出的规范是：与 None 这类单例比较时始终用 is / is not，绝不要用相等运算符；同时不要用 == 或 is 去和 True / False 比较（直接写 if flag: 即可）。
  • and / or 返回的不是布尔值。官方文档《6.11 布尔运算》明确写道，and 与 or 都不限制返回值必须是 False / True，而是返回最后被求值的操作数。所以 1 and 2 得 2，'' or 'foo' 得 'foo'；只有 not 一定返回布尔值。这既是「s or '默认值' 能给空字符串兜底」这类写法的原理，也是把它当布尔值用时的陷阱来源。
  • // 是「向下取整」，不是「抹掉小数位」。官方文档说明整除结果始终向负无穷方向取整，于是 -7 // 2 得 -4，而不是截断式的 -3；% 的结果符号跟随除数，-7 % 2 得 1、7 % -2 得 -1。本课处理的字数、条数都是非负数，不受影响；一旦数据里出现负数（例如与均值的差值），这个差别就会显形。
  • / 总是返回浮点数。官方教程用 8 / 5 得 1.6 举例，并点明「除法运算总是返回浮点数」——即便能整除，4 / 2 也会得到 2.0 而不是 2。需要整数结果时，拿它去做列表下标或字符串重复次数会直接报错，此时应改用 //。
  • + 的两副面孔，以及它不能跨类型。对数字它是加法，对字符串 / 列表它是拼接；两者的共同点是两个操作数类型必须相容。'字数：' + 880 会抛 TypeError，正确做法是转换类型（'字数：' + str(880)）或直接用 f-string。
  • 浮点数比较不能想当然。官方教程《浮点算术：问题和限制》指出，因为 0.1 无法用二进制小数精确表示，0.1 + 0.1 + 0.1 == 0.3 的结果是 False。涉及小数比较时，通常改用 math.isclose()，或先把数值四舍五入到需要的位数再比。
  • 位运算符与逻辑运算符不能互换。& | 是按位运算，and or 是逻辑运算：前者优先级高于比较运算，后者低于比较运算，且 & 不具备短路求值特性。本课只要求认得这两个符号，不要求使用。

✅ 核查说明：以上各条均对应第九节的官方文档条目；其中涉及具体求值结果的部分（-7 // 2、1 and 2、0.1 + 0.2 == 0.3 等）另经本地解释器实跑验证。边界结论只说明「本课覆盖到哪里」，不代表这些用法本身不可用。
