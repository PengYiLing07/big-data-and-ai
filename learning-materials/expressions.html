📖 三、概念的通俗解释

表达式是「能算出一个值」的写法。这个词的重点全在最后四个字上：只要一段写法被 Python 求值之后产出一个值，它就是表达式。 3 + 5 产出 8，len(body) 产出正文长度，chars < 900 产出 True 或 False—— 连单个 5、单个变量名 title、单个字符串 "发稿" 都是表达式，它们算出的是自己。

表达式由三类东西拼成：操作数（要加工的数据：字面值、变量、函数调用）、运算符（加工的规则）、 括号与函数调用（改变结合顺序、把更多运算拉进来）。把运算符换成对应的内置函数，结果完全一样： 2 + 3 与 operator.add(2, 3) 都得 5，本页实跑核对时还确认了 (5).__add__(3) 得 8—— 这说明运算符只是运算的一种简写形式，运算本身才是内核。

真正让「表达式」这个概念立起来的，是它和语句的对照。x = 5 是一条赋值语句：它让名字 x 绑定到 5， 但整条语句不产出值——所以它不能塞进算术式，也不能当 if 的条件。本页实跑时验证了这一点：直接写 if (x = 5):， Python 3.12 报错 SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?。 另一条边界同样值得记住：print() 是函数调用，是表达式；但它的返回值是 None， 所以 total = print(len(body)) 之后 total 是空值而不是字数——小计得靠变量或内置函数 len，不能靠 print。

💡 一个类比 表达式可类比为编辑流程里的「一道可出结果的工序」：给出原料、指定加工方式，它一定产出一个成品。如果一道工序做完什么成品都不产出，它在流程里就不占位置——这正是语句与表达式的分界。这一类比属辅助理解的通俗化说法，非官方定义。

反过来，下面这些不是表达式，因为它们求值后不产出值：赋值语句 n = 5 与 count += 1、print 这类「以语句身份出现」的调用之外的语句 import re / def / return / break / continue / pass / del，以及 if / for / while / with 这些复合语句。注意：if 作语句时不产出值，写成条件表达式 a if cond else b 才有值——这是最容易看走眼的一条。

求值的机制：四步，外加两种「提前收工」

环节说明
1. 确定操作数先把每个操作数求值出来（len(body) 先算出字数），复杂操作数按各自的规则递归求值。
2. 按优先级分组依据运算符优先级决定哪两个操作数先结合。同级运算符大都从左至右，只有幂 ** 与条件表达式从右至左。
3. 查类型的运算规则同一个符号在不同类型上行为不同：+ 对数字是加法、对字符串是拼接；* 对整数与序列是重复。
4. 产出结果算术得数字，比较 / 成员 / 身份得布尔值，逻辑得操作数本身，条件表达式得被选中的分支。
短路求值and / or 在结果已能确定时不再求值右侧；条件表达式只求值被选中的那一支。1 and 2 得 2。
（短路与布尔返回值的完整规则见 Python 运算符，本页只讲它属于「求值顺序」这一环。）
链式比较特例1 < x < 10 等价于 1 < x and x < 10，但中间的 x 只求值一次，且 7 < y < 5 得 False（不是被当成 True and 5）。

结合性补充：同级运算符通常从左至右结合，只有幂与条件表达式从右至左。因此 2 ** 3 ** 2 等价于 2 ** (3 ** 2)，结果为 512。

三个「特殊表情」的表达式

写法它是什么什么时候用得上
a if cond else b条件表达式（Python 2.5 引入，常被误称为「三元运算符」）。else 分支不可省略——省略直接报 SyntaxError。一行内二选一：level = "短稿" if chars < 900 else "长稿"
n := 表达式赋值表达式（PEP 572，Python 3.8 引入），会同时完成赋值并产出这个值。需要在条件里赋值并立刻比较：if (n := len(body)) > 900:
lambda 参数: 表达式匿名函数，整个 lambda 本身就是一个表达式，产出函数对象。临时给 sorted(key=...) 传一段小逻辑，不值得为它写 def

其中赋值表达式有一条硬边界：它必须被括号包起来才能单独出现。裸写 n := 5 会报 SyntaxError，加括号写成 (n := 5) 才有值。原因正是本页的主线——不加括号时，那个位置需要的是语句，而赋值表达式给的是值。

🚀 六、一个具体应用场景

场景沿用新闻编辑室里的常见动作：看一条稿件够不够格推送。这件事从取值到判断，每一步都是表达式；写完之后反过来读一遍，就能体会「表达式」这个概念在真实代码里到底出现在哪些位置。 本例正文由 12 字的句子重复 30 次构成（共 360 字），因此计算出的阅读时长较长；把 body 换成稿件的真实正文，read_seconds 就会跟着变。 

# 场景：把一条稿件的关键数字算出来，判断能否推送
title = "地铁新票价方案今日公布，通勤族最关心这三个问题"
body = "记者今日从市发改委获悉，" * 30   # 模拟正文

# ① 表达式出现在赋值语句的右侧：先算出值，再绑定名字
chars = len(body)                                  # 函数调用
read_seconds = chars * 60 // 300                   # 算术表达式

# ② 表达式当 if 的条件：结果必须是布尔值
if read_seconds > 8:
    print("篇幅偏长，需配摘要")

# ③ 表达式当函数参数：先在括号里算完，再交给 print
print("预计阅读", read_seconds, "秒")

# ④ 条件表达式：一行内二选一
level = "短稿" if chars < 900 else "长稿"

# ⑤ 赋值表达式：在条件里赋值，顺手把结果用起来
if (n := len(title)) > 20:
    print(f"标题 {n} 字，超出建议长度")

# ⑥ 表达式套表达式：结果继续当下一层的操作数
ready = (chars > 0) and ("票价" in title)
print("可推送" if ready else "需人工复核")

以上代码在本仓库 Python 3.12.10 解释器（.venv\Scripts\python.exe）实跑，输出如下：

篇幅偏长，需配摘要
预计阅读 72 秒
标题 23 字，超出建议长度
可推送

这段代码里值得单独记住的三点

写法它在做什么
chars = len(body)等号右边是表达式，左边是名字。Python 先算右边，再把值绑定到左边——所以「表达式在语句内部」是常态，而不是例外。
if (n := len(title)) > 20:赋值表达式把「算长度」和「拿它比较」合并成一步。如果只在条件里用一次、后面不再用 n，通常会拆成两行更易读；它的价值在于需要复用这个值时不必算两遍。
"短稿" if chars < 900 else "长稿"条件表达式必须有 else。想表达「不满足就什么都不做」，那是 if 语句的职责，不该硬写成条件表达式。
✅ 核查说明（人工） 本页所有求值结论均在本地 Python 3.12.10 中实跑核对，与官方文档描述一致：2 + 3 得 5、operator.add(2, 3) 得 5、1 < 5 < 10 得 True、7 < 10 < 5 得 False、1 and 2 得 2、"" or "默认" 得 '默认'、print(...) 返回 None、4 / 2 得 2.0、-3 ** 2 得 -9、2 ** 3 ** 2 得 512、0.1 + 0.2 == 0.3 得 False。两处语法边界同样实测：if (x = 5): 报 SyntaxError（提示 Maybe you meant '==' or ':=' instead of '='?），条件表达式缺 else 报 SyntaxError: expected 'else' after 'if' expression。另有两项来自字节码观察（dis 输出）：n = 5 只有 LOAD_CONST / STORE_NAME 两条指令，没有求值结果被留下；而 n = a + b * c 能看到 BINARY_OP * 先于 BINARY_OP + 的层级——注意若写成全字面值 n = 2 + 3 * 4，解释器会在编译期直接折叠成常量 14，这属优化行为，不影响「表达式按优先级求值」的语义。

⚠️ 七、易混与边界

  • 表达式 vs 语句，判据只有一条：能不能算出一个值。本页的核心分界就在这里。x = 5、import re、return、break、if ...: / for ...: 都不产出值，所以是语句；3 + 5、len(body)、[x for x in xs] 都产出值，所以是表达式。最典型的反例是 if：作语句时无值，写成 a if cond else b 才有值。
  • 赋值是语句，赋值表达式才是表达式——两者不能互相顶替。n = 5 是语句，不能被嵌套，也不能当条件，所以 if (n = 5): 直接报语法错误（实跑得到的提示是 Maybe you meant '==' or ':=' instead of '='?）。n := 5 是表达式，但它必须加括号才能单独出现——裸写同样报错。这条边界说明「有值」和「能用」是两个层次的问题。
  • 表达式必须有产出；None 也是一个产出。print(...) 是表达式，它的返回值是 None。因此 total = print(chars) 之后 total 是 None 而不是 chars——想拿到字数得用 chars = len(body)，或者先 print 再赋值，别指望 print 把值交出来。
  • 写成合法代码 ≠ 得到目的结果。1 + 2 得 3，可"字数：" + chars 会抛 TypeError：类型不相容时运算直接失败，而不是自动转换。这类错误属于表达式能跑但意图没实现，排查时要看的是参与运算的两个对象分别是什么类型（细节见 变量与数据类型）。
  • 条件表达式不是「省略版的 if」。a if cond else b 的 else 分支不可省，实跑缺 else 会报 SyntaxError: expected 'else' after 'if' expression。它产出的是一个值，适合赋值与传参；要执行的是「动作序列」，仍应写 if 语句。
  • 短路不是「跳读代码」，而是「不求值」。chars > 0 and 900 // chars > 1 之所以安全，是因为 chars 为 0 时右侧整个不会被求值；反过来，若把顺序写反，900 // 0 会直接抛 ZeroDivisionError。同理，条件表达式只求值被选中的那一支，另一支即使写错了也不会执行——这既是优化，也是隐藏 bug 的来源。
  • 浮点数比较与优先级两个老坑，判断的正是表达式。0.1 + 0.2 == 0.3 得 False（应改用 math.isclose()）；-3 ** 2 得 -9 而非 9，因为 ** 高于一元负号。两者都属「写法正确、结果反直觉」，只有理解求值顺序才能预判。运算符号本身的完整清单见 Python 运算符。
  • 本页边界：表达式不涉及「怎么组织代码」。函数定义、模块拆分、异常处理这些控制程序结构的内容不在本页范围内（分别见 函数、模块与包、异常处理）。另外，推导式、生成器表达式虽然也是表达式，其完整写法另见 推导式，本页只把它们列入「哪些写法算表达式」的清单。
