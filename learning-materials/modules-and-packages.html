🧭 一、学习目标

学完本页后，读者应该能够回答：

  • 「模块」在文件系统上是指什么？「包」又是指什么？两者是什么关系？
  • 执行 import news_tools.clean 时，Python 依次做了哪几件事？为什么第二次导入不会再执行一遍文件里的语句？
  • import X、from X import Y、import X as Z、from X import * 分别把什么名字放进了当前命名空间？
  • if __name__ == "__main__": 解决的是什么问题？包里的入口为什么叫 __main__.py？
  • pip install 装好的东西放在哪里？为什么更推荐装进虚拟环境，而不是直接装到系统 Python 里？

❓ 二、核心问题

  • 它解决什么问题——处理一批稿件的代码从几十行涨到几百行，还要被多个脚本反复使用时，如何把它切成可独立维护、可被反复取用的单元，而不是每次复制粘贴？
  • 它由什么组成——模块是一个 .py 文件，包是带 __init__.py 的目录；import 语句把「定位 → 执行一次 → 绑定名字」三步串起来；__name__ 的值决定同一个文件是被当作可导入模块，还是被当作入口脚本。
  • 它和相邻概念怎么区分——模块 / 包 / 库 / 框架各指什么？import 与 pip install 为什么是两件事？「包」这个词为什么在两种语境下含义不同？
  • 它的边界在哪——导入只能找到 sys.path 覆盖得到的位置；同名文件会遮蔽标准库；同一个解释器会话内模块不会重新加载；相对导入只在包内成立。

📖 三、概念的通俗解释

模块就是一个 .py 文件。Python 官方教程给出的定义是：「模块是包含 Python 定义和语句的文件。其文件名是模块名加后缀名 .py。在模块内部，通过全局变量 __name__ 可以获取模块名。」这句话包含三层意思：文件名决定模块名；文件里可以放函数、类等定义，也可以放直接执行的语句；文件自己被赋予了一个名字，代码可以读到这个名字。模块让一组相关定义拥有自己的名字和独立的符号表，模块内定义的所有函数都把该模块的符号表当作全局符号表使用。

官方教程还指出：「模块包含可执行语句及函数定义。这些语句用于初始化模块，且仅在 import 语句 第一次 遇到模块名时执行。」也就是说，import 做的不只是「取用函数」，它会真的把这个文件从头执行一遍——只不过每个解释器会话里只执行一次。与之配套的另一条规则是：「为了保证运行效率，每次解释器会话只导入一次模块。如果更改了模块内容，必须重启解释器；仅交互测试一个模块时，也可以使用 importlib.reload()。」这解释了一个常见困惑：改了被导入的文件、重新运行主脚本却看不到变化——因为解释器进程还是原来那个。

包是「装模块的目录」。官方教程的表述是：「包是通过使用『带点号模块名』来构造 Python 模块命名空间的一种方式。例如，模块名 A.B 表示名为 A 的包中名为 B 的子模块。」并且「需要有 __init__.py 文件才能让 Python 将包含该文件的目录当作包来处理（除非使用 namespace package，这是一个相对高级的特性）」。这一条设计的目的很实在：防止某个同名目录不知不觉挡住后面搜索路径上的有效模块。最简单的 __init__.py 可以是空文件，也可以放包的初始化代码或 __all__ 变量。

最后一个容易混的点：pip install 装的东西，与 import 导入的「包」不是同一个含义。Python 打包用户指南在开头专门澄清：「这里的『package』一词用于描述待安装的软件集合（即 distribution 的同义词），它并不指在源码中导入的那种包（即模块的容器）。」所以「装好了」和「导得进来」是两件事：装在哪套环境里，只有那套环境里的解释器导得进来。

💡 一个类比 模块可类比为编辑部里一份单独成册的「分工文件」：文件自己有名字，里面写着若干可被反复呼叫的工序（函数）；别的文件要用，就在开头写明「调用哪一份」。包则可类比为把这些分工文件装进一个带标签的抽屉：抽屉本身有个名字，抽屉内每份文件各有各的名字，合起来用「抽屉.文件」的方式指称。这一类比属于帮助理解的通俗化说法，非官方原文。
💡 一个类比 if __name__ == "__main__": 可类比为一份文件末尾附加的「仅在本人被单独派活时才照办」的操作说明：这份文件被别人借去当参考（被导入）时，末尾那段操作说明不会自动执行；只有把它当成独立任务派出去（直接运行）时才会走一遍。官方文档对它的解释是，模块通过检查自己的 __name__ 即可发现自己是否运行于顶层环境，从而让「一些代码仅当模块不是被导入语句初始化的时候才执行」。这一类比属于帮助理解的通俗化说法，非官方原文。

四种导入写法各自绑定的名字

写法当前命名空间里多出什么使用时怎么写注意事项
import fibo模块名 fibofibo.fib(1000)不会把模块里的函数名直接加进当前命名空间，因此一般不会与其他名字冲突
from fibo import fib, fib2函数名 fib、fib2fib(1000)不引入模块名，此时 fibo 在当前代码块中是未定义的名称
import fibo as fb别名 fbfb.fib(1000)适合模块名过长、或与已有名字冲突时；绑定的是 as 之后的名称
from fibo import fib as f别名 ff(1000)同样只绑定别名，被导入的原始名称不出现
from fibo import *所有不以 _ 开头的名称直接用名字官方教程明确提示：大多数情况下不要用这个功能，它可能会覆盖已经定义过的名称

模块 / 包 / 库 / 框架

说法指的是什么判断依据
模块（module）一个 .py 文件，文件名即模块名能被 import 的最小单位
包（package，源码语境）装模块的目录，靠 __init__.py 被识别为包；可嵌套子包，模块名写成 A.B目录 + __init__.py
包（package，安装语境）可安装的软件集合，即 distribution能否被 pip 安装；与源码里的包名可以不同
库（library）一组可复用的模块集合的统称，不是 Python 的语法概念习惯说法；标准库指随 Python 一起发布的那批模块
框架（framework）调用关系由框架决定的一套库，代码按框架要求填空控制反转；概念层面区分，非语法规定

🚀 六、一个具体应用场景

前 8 课的代码通常写成一段一段的散装脚本：清洗文本的几行、统计字数的几行、切分句子的几行、出稿的几行。这些代码每次跟着具体那份稿件走，换一份数据就要复制一遍。把第 7 课的函数封装思路再往前推一步，就可以把这些函数分门别类放进一个包里，各自成文件，主脚本只负责调用。

目录结构安排如下（__init__.py 让目录被识别为包，__main__.py 为包提供命令行入口）：

news_tools/
├── __init__.py      # 标记为包；可用 __all__ 指定 from news_tools import * 时导入哪些子模块
├── clean.py         # 清洗：clean_text / split_sentences
├── stats.py         # 统计：count_chars / top_words
├── report.py        # 出稿：make_title / summary
└── __main__.py      # 入口：python -m news_tools 时执行这里

包内各文件用相对导入互相引用。report.py 依赖同一包里的 clean 与 stats：

# news_tools/report.py
"""出稿：把处理结果拼成一句可读的小结。"""

from .clean import clean_text
from .stats import count_chars, top_words

def make_title(text, max_len=12, ellipsis="…"):
    """把长标题截断为不超过 max_len 个字符的短标题。"""
    text = clean_text(text)
    return text if len(text) <= max_len else text[:max_len] + ellipsis

def summary(raw):
    """把一条稿件压缩成一行小结。"""
    text = clean_text(raw)
    top = top_words([text], n=1)
    top = top[0][0] if top else "-"
    return "%s（%d 字，高频片段：%s）" % (make_title(text), count_chars(text), top)

包的入口 __main__.py：用 main() 函数封装主要行为，再交给 sys.exit()，这是官方文档推荐的写法。

# news_tools/__main__.py
"""包的入口：python -m news_tools 时执行这里。"""

import sys

from .report import summary

def main():
    raw = " 　地铁票价调整方案 公布，首周客流下降 3%。  相关部门表示将继续观察。 "
    print("小结：", summary(raw))
    return 0

if __name__ == "__main__":
    sys.exit(main())

在仓库根目录下运行，得到下面这一行输出：

$ python -m news_tools
小结： 地铁票价调整方案 公布，…（32 字，高频片段：地铁）

包内单个模块也可以单独运行来做自测，比如给 clean.py 末尾加一段：

# news_tools/clean.py 末尾
if __name__ == "__main__":
    demo = " 　地铁票价调整方案 公布。  客流下降。 "
    print(clean_text(demo))
    print(split_sentences(clean_text(demo)))
$ python -m news_tools.clean
地铁票价调整方案 公布。 客流下降。
['地铁票价调整方案 公布。', '客流下降。']
✅ 核查说明（人工） 上面这段示例已在 Python 3.13 下实际运行通过：python -m news_tools 输出「小结： 地铁票价调整方案 公布，…（32 字，高频片段：地铁）」，python -m news_tools.clean 走的是模块末端的自测分支。作为对照组，直接执行 python news_tools/report.py 会立刻报错 ImportError: attempted relative import with no known parent package，这正是「包内模块不要直接按路径运行」的现场证据。这一段属辅助理解示例，非某个来源的原文代码。

⚠️ 七、易混与边界

  • 模块、包、库、框架不是同级概念。模块与包是 Python 的语法概念（文件、目录），有明确定义与判定依据；「库」和「框架」是习惯说法，描述的是复用范围与调用关系的不同，并没有对应的语法特征。看到「装个库」时，指的通常是安装语境下的「包」。
  • 「包」一词有两种含义，混用会出错。Python 打包用户指南在篇首澄清：安装语境中的「package」指的是可安装的软件集合（distribution 的同义词），并不指源码里 import 的那种包。因此「这个包名是什么」可能是在问 pip install 后面跟什么，也可能是在问 import 后面跟什么，两者不一定一致。
  • import X 与 from X import Y 的区别在于「命名空间里多了什么」。前者多的是模块名，函数要写成 X.Y()；后者多的是函数名，模块名并未引入。用 from X import * 会把所有不以 _ 开头的名字都引进来，官方教程明确提示大多数情况下不要用，因为它可能覆盖已经定义过的名称。
  • 模块只在第一次导入时执行，且每个解释器会话只导入一次。官方教程的原话是「这些语句用于初始化模块，且仅在 import 语句第一次遇到模块名时执行」，并提示「如果更改了模块内容，必须重启解释器；仅交互测试一个模块时，也可以使用 importlib.reload()」。把重活写在模块顶层语句里，会导致「导入即执行」，也难以测试。
  • pip install 成功不等于 import 得到。安装是把文件放进某套解释器的 site-packages；如果运行脚本用的是另一套解释器（系统 Python 与项目虚拟环境是最常见的组合），照样会报 ModuleNotFoundError。排查时的第一件事是确认「安装时用的 python」与「运行时用的 python」是不是同一个。
  • 同名文件会遮蔽标准库模块。官方教程指出：脚本所在的目录先于标准库所在的路径被搜索，「这意味着，脚本所在的目录如果有和标准库同名的文件，那么加载的是该目录里的，而不是标准库的」。把自己写的文件命名为 random.py、csv.py、statistics.py 就可能触发这个问题，报错信息往往指向标准库内部，较难识别。
  • 包内模块不要按文件路径直接运行。PEP 328 说明相对导入靠模块的 __name__ 判断其在包中的位置；当名字里不含包信息（例如被设为 __main__）时，相对导入会按顶层模块解析，与文件实际位置无关。所以包内模块要用 python -m 包名.模块名 运行，而不是 python 包名/模块名.py。
  • 包的作用范围受搜索路径限制。能被导入的模块，必须位于 sys.path 覆盖得到的位置。把源码目录随便放一个位置、或把包放在与运行位置无关的目录，都会导致找不到；反过来，包也不是分发单元，把代码交给别人通常还要配合打包与安装。此外 __init__.py 在 namespace package 这种相对高级的形态下可以省略，但常规用法仍需要它。
