📖 三、概念的通俗解释

pandas 是一个用于表格数据的 Python 库。它提供两个最基本的结构：Series 和 DataFrame。按官方文档的说法，Series 是「一维的、带轴标签的数组」，DataFrame 是「二维的、带标签的数据结构，各列可以有不同的类型」——后者可以被看成类似电子表格或 SQL 表，也可以被看成「由多个 Series 组成的字典」。

关键在于「带标签」这三个字。普通列表只有位置：第 0 个、第 1 个。DataFrame 的每一行有一个行索引（可以是默认的 0、1、2，也可以改成日期或稿件编号），每一列有一个列名。要取某一个值，既可以说「第 0 行第 2 列」（按位置），也可以说「评论编号为 A001 那一行的字数」（按标签）。这两种说法分别对应 iloc 和 loc，是初学者最容易混的一对。

而「一次对整列做运算」这件事，是 pandas 真正省力的地方。df["文本长度"] = df["评论内容"].str.len() 这一行里没有循环，它对每一行都算了一次长度。这与 NumPy 的向量化思路一致：把「逐条处理」交给底层的数组运算，代码更短，也通常更快。

💡 一个类比 DataFrame 可类比为一张带固定表头的采访记录台账：横向是字段（来源、字数、情感标签），纵向是每一条记录；每一行左端还贴了一个编号，这个编号就是行索引。loc 相当于「按编号或字段名去查」，iloc 相当于「按第几行第几格去找」。这一类比属于帮助理解的通俗化说法，非官方原文。
💡 一个类比 从字典走向 DataFrame，可类比为把散装卡片装订成册。字典的键（「字数」「来源」）变成列名，字典里每个键对应的那一串值（原本是一个列表）变成一列，也就是一个 Series；所有列共用同一份行编号，因此可以整列比较、整列统计。这一类比属于帮助理解的通俗化说法，非官方原文。

⚙️ 五、核心机制 / 组成

一张 DataFrame 可以拆成四个组成部分。理解这四部分各自管什么，是理解后面所有索引与运算规则的前提。

组成部分作用 / 说明
行索引 index每一行的名字标签。不指定时自动生成 RangeIndex（0、1、2……）。索引值允许重复，但重复后某些依赖唯一性的操作会报错。
列名 columns每一列的名字标签，相当于字段名。按列取值最常用的写法就是 df["列名"]。
值 values真正被存储的数据，底层通常是一个或多个 NumPy 数组。Series 与 DataFrame 都能被大多数 NumPy 函数直接接受。
每列类型 dtype同一列内部类型一致，不同列可以不同。info() 会列出每一列的非空数量与类型，是判断「这份数据能不能直接算」的第一手信息。

Series 与 DataFrame 的关系

对象维度通俗说法典型取值
Series一维带标签的一列数据df["字数"]、df.loc[0]（取一行也是一个 Series）
DataFrame二维共享同一行索引的多个 Series 组成的字典df 本身；df[["来源","字数"]] 取多列得到的是 DataFrame

官方《数据结构简介》给出的表述是：DataFrame 是「二维的、带标签的数据结构，各列可以有不同的类型」，可以理解成类似电子表格或 SQL 表，也可以理解成「由 Series 组成的字典」。注意一个常见细节：用单个中括号取一列得到的是 Series，用双重中括号取多列得到的是 DataFrame——多一个中括号，返回类型就变了。

🚀 六、一个具体应用场景

编辑部从后台导出了一份新闻评论数据集 comments.csv，字段包括「来源」「评论内容」「情感标签」「发布时间」。要回答两个问题：正负样本的比例是否均衡？评论长度集中在什么范围？下面这一段把第 12–13 课涉及的主要方法串成一条完整链路。 

# 场景：加载新闻评论数据集，看正负样本分布与文本长度分布
import pandas as pd

# ① 读入：CSV 若不是 UTF-8 编码（常见为 GBK），要显式指定 encoding
df = pd.read_csv("comments.csv", encoding="utf-8")

# ② 查看：先确认形状、类型与非空数量，再决定怎么处理
print(df.shape)            # (行数, 列数)
print(df.info())           # 每列的非空数量与 dtype
print(df.head(3))          # 前 3 行，确认字段是否对得上

# ③ 清洗：新增「文本长度」列；处理缺失的情感标签
df["文本长度"] = df["评论内容"].str.len()
print(df["情感标签"].isna().sum())          # 有多少条没打标签
df["情感标签"] = df["情感标签"].fillna("未标注")
df = df.dropna(subset=["评论内容"])               # 正文为空的行去掉

# ④ 筛选：多个条件要用括号分组，连接用 & 而不是 and
long_neg = df.loc[(df["情感标签"] == "负面") & (df["文本长度"] > 50),
                  ["来源", "文本长度"]]
print(long_neg.shape)

# ⑤ 统计与分组：看样本分布 + 看长度分布 + 按来源比较
print(df["情感标签"].value_counts())     # 正负样本分布
print(df["文本长度"].describe())          # 长度分布：均值与分位数
by_source = (df.groupby("来源")["文本长度"]
               .mean()
               .sort_values(ascending=False))  # 链式操作
print(by_source)

# ⑥ 导出：写回 CSV 时同样要指定编码；index=False 表示不写行号列
by_source.to_csv("按来源平均字数.csv", encoding="utf-8-sig")

这一段是文章级别的示例，用于说明各方法在流程中的位置，属于辅助理解示例，非某个来源的原文代码。其中 encoding="utf-8" 与 encoding="utf-8-sig" 的写法依据 pandas 官方 read_csv / read_excel 页面中关于 encoding 参数的说明；utf-8-sig 属于 Python 标准编码之一，写出的文件带 BOM，用 Excel 直接打开中文不易乱码。

⚠️ 七、易混与边界

  • loc 按标签，iloc 按位置，切片语义还不一样。官方《索引与选择数据》说明：loc 的标签切片首尾都包含（df.loc["a":"c"] 取 a、b、c 三行），iloc 的位置切片上界不含（df.iloc[1:3] 取位置 1、2 两行）。一个常见误解是「两者可以互换」——当行索引恰好也是 0、1、2 时，取单个值的结果往往相同，但一旦索引换成了日期或编号，loc 里写整数就不再表示位置。
  • 多个筛选条件必须用括号，且只能用 & / | / ~。官方文档明确指出布尔向量之间要用 |（或）、&（且）、~（非），并且必须加括号以避免运算符优先级导致的错误。写成 df[df["a"] > 1 & df["b"] < 2] 通常不会按预期工作，而且未必报错，只是结果悄悄不对。
  • 「空」不等于 None，也不能用 == 判断。官方《缺失值处理》特别提示：np.nan == np.nan 的结果是 False，pd.NaT == pd.NaT 同样是 False。判断缺失要用 isna() / notna()，而不是比较运算。缺失值在算术与比较中会「传播」——一个缺失值参与运算，结果通常仍是缺失值。
  • 不要对筛选结果直接赋值。像 df[df["字数"] > 50]["标签"] = "长" 这样的链式写法，中间那一步返回的对象通常不是原表本身，赋值可能不会反映到 df 上。稳妥做法是一次性用 df.loc[条件, "标签"] = "长"。官方索引文档专门对这一类链式索引的风险给出了提示。
  • groupby 的结果不是「原表的子集」，而是「每组一行的新表」。默认情况下分组键会变成结果的索引（as_index=True），因此结果的行数等于组数，而不是原表的行数。若希望分组键仍是一列普通数据，可加 as_index=False，或在结果上继续链式调用 .reset_index()。另外官方文档说明 dropna 默认为 True，意味着分组键中的缺失值所在行会被丢弃——这会静默改变样本量。
  • pandas 不是万能的边界。它擅长的是「单机内存装得下」的表格数据。数据量大到内存放不下时，通常需要换成分块读入（chunksize）或改用分布式工具；对图片、音频等非表格数据，pandas 提供不了直接的帮助。

✅ 核查说明：本节六条的技术结论均以 pandas 官方文档为依据。切片语义、布尔索引的括号要求与链式索引提示见《索引与选择数据》；缺失值比较行为见《缺失值处理》；as_index 与 dropna 的默认行为见 DataFrame.groupby 页面；「Group by 是拆分—应用—合并」的概括见《Group by: split-apply-combine》。具体链接见第九节。
