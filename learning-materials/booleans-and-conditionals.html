📖 三、概念的通俗解释

True 与 False 是 Python 的两个内置常量，官方文档把它们与 None 一起列为关键字，因此不能被赋值。它们属于 bool 类型，只有两个取值，用来表示「成立 / 不成立」。

比较运算负责把数据「换算成」真假。官方文档指出，<、>、==、>=、<=、!= 这六个运算符比较两个对象的值，而 is / is not 比较对象的标识号（是不是同一个对象），in / not in 则做成员检测。三者常被统称为比较运算，但它们回答的是三个不同的问题。

and / or / not 负责把多个真假条件组合起来。这里有一个最容易踩空的地方：官方文档明确写道，「and 和 or 都不限制其返回的值和类型必须为 False 和 True，而是返回最后被求值的操作数」。因此 "标题" and "导语" 的结果是字符串 "导语"，而不是 True。只有 not 例外，它必须创建新值，所以总是返回布尔值。

💡 一个类比 条件判断可类比为编辑部的分稿流程：稿件先送第一道审核（if），不符合条件就转到下一道（elif），全部不符合才进入兜底通道（else）。每一道审核只回答「是 / 否」，但决定后续走向。这一类比属于帮助理解的通俗化说法，非官方原文。
💡 一个类比 短路求值可类比为值班主任的逐条确认：and 是从左往右逐条检查，只要有一条不成立就当场叫停，后面的条目不再检查；or 则是一旦有条成立就当场放行。被跳过的条目根本没有被求值，因此它内部的计算不会发生。这一类比属于帮助理解的通俗化说法，非官方原文。

⚙️ 五、核心机制 / 组成

一次条件判断由三部分配合完成：比较运算把数据换算成真假，布尔运算把多个真假组合成一个，缩进与分支语句决定按这个结果执行哪一段代码。

比较运算符的分类与职责

运算符比较什么说明
< <= > >=两个对象的值（次序）官方文档指出，次序比较默认没有提供，未实现比较方法的内置类型会引发 TypeError；字符串按 Unicode 码位数字值进行字典序比较。
== !=两个对象的值（相等性）两个对象不要求类型相同，因此 5 == 5.0 为真；数值类型可进行类型内部与跨类型的比较。
is is not对象的标识号当且仅当 x 与 y 是同一对象时为真，标识号可用 id() 获取。PEP 8 建议单例对象（如 None）的比较总是用 is 或 is not。
in not in成员是否存在于容器中对字符串而言，当且仅当 x 是 y 的子串时为真；空字符串被视为任何字符串的子串，因此 "" in "abc" 为真。

布尔运算与短路求值

写法求值结果（官方文档表述）短路行为
x or y先对 x 求值；如果 x 为真则返回该值，否则对 y 求值并返回其结果值仅当 x 为假时才求值 y
x and y先对 x 求值；如果 x 为假则返回该值，否则对 y 求值并返回其结果值仅当 x 为真时才求值 y
not x如果 x 为假则产生 True，否则产生 False总是返回布尔值，不返回操作数

官方文档补充说明：and 与 or 都不限制返回值必须为 False 和 True，而是返回最后被求值的操作数。这一性质使 s or 'foo' 这类写法可以用于给空字符串设置默认值。

分支语句与真值检测

组成部分作用 / 说明
if 条件:必备的第一个分支。官方教程说明：可有零个或多个 elif 部分，else 部分也是可选的。
elif 条件:else if 的缩写，用于避免过多缩进；只有在前面所有条件都不成立时才会被检查。
else:兜底分支，不带条件，前面全部不成立时执行。
缩进Python 用来组织语句的方式，同一块语句的每一行缩进必须相同。官方教程的编码风格建议是用 4 个空格，不要用制表符。
真值检测条件位置上并不要求出现布尔值：False、None、任何数值类型的零、以及空字符串与空容器都被解读为假，其他值都被解读为真。
条件表达式官方文档定义：x if C else y 首先对条件 C 而非 x 求值；C 为真则求值并返回 x，否则求值并返回 y。

🚀 六、一个具体应用场景

给一批稿件标题和评论打上「正面 / 负面 / 中性」标签，是内容运营与舆情梳理中最常见的整理工作。在还没有学习任何机器学习方法之前，最原始的实现方式就是准备两张关键词表，再用条件判断逐条比对——这可以看作情感分析最初级的形态。 

# 场景：按关键词给标题与评论打标签
POSITIVE = ["好", "赞", "顺利", "提升", "满意"]
NEGATIVE = ["差", "糟", "拥堵", "投诉", "不满"]

def tag_by_keyword(text):
    # in 做成员检测：对字符串而言即「是否为子串」
    hit_pos = [w for w in POSITIVE if w in text]
    hit_neg = [w for w in NEGATIVE if w in text]

    # 先判负面：负面词一旦出现即优先，避免被正面词冲淡
    if hit_neg:
        tag = "负面"
    elif hit_pos:
        tag = "正面"
    else:
        tag = "中性"       # 兜底：也可能只是「没覆盖到」，见下文说明

    return tag, hit_pos, hit_neg

# 批量处理一批标题与评论
texts = [
    "地铁票价调整方案公布，市民表示满意",
    "施工期间道路拥堵，接到的投诉明显增加",
    "这服务真是绝了",
]

for t in texts:
    tag, pos, neg = tag_by_keyword(t)
    print(f"{tag}｜命中 正面{pos} 负面{neg}｜{t}")

# 输出：
# 正面｜命中 正面['满意'] 负面[]｜地铁票价调整方案公布，市民表示满意
# 负面｜命中 正面[] 负面['拥堵', '投诉']｜施工期间道路拥堵，接到的投诉明显增加
# 中性｜命中 正面[] 负面[]｜这服务真是绝了      ← 明显判错

# 短路求值的常见用法：先判空，避免对空字符串做无意义操作
title = ""
if title and "地铁" in title:
    print("命中选题")
else:
    print("标题为空或未命中，跳过")   # title 为空字符串即「假」，右侧不再求值

# 条件表达式：一行内完成二选一
name = ""
author = name or "未署名"            # or 返回操作数本身，空字符串被替换为默认值
print(author)                          # 未署名

这一段是文章级别的示例，用于说明条件判断在打标签任务中的实际写法，属于辅助理解示例，非某个来源的原文代码。

🔚 收尾 · 规则法为什么不够 上面的实现把「不命中」直接等同于「中性」，而这两件事并不是一回事。评论「这服务真是绝了」不含任何负面词，规则法给出「中性」，但人工阅读会判断为差评——这不是代码写错了，而是方法本身的边界。规则法能看到的只有「某个词是否出现过」这一个信号，它看不见词与词之间的关系，也看不见语气。

具体地说，规则法至少在三类语言现象上会系统性失效。第一类是反讽与语义反转：「绝了」「真有你的」这类表达没有固定的情感极性，褒贬完全取决于语境，任何固定关键词表都无法同时覆盖两种用法。第二类是否定与双重否定：「不满意」里的「满意」是正面词，但前缀「不」把它翻转了；如果只做子串匹配，"满意" in "不满意" 仍然为真，判断会直接反向。第三类是程度与语境依赖：「票价调整」本身不含情感，但放在涨价语境里往往引发负面情绪，这类判断需要读完上下文才能做出。

更关键的是，规则法的输出里，「真的没有情感倾向」和「关键词表没覆盖到」这两种情况结果完全相同，都是「中性」，因此无法仅凭输出判断系统在哪里失效，也就无法通过加词表来彻底修好它。这种「靠人写出全部规则」的路线在真实文本上的天花板，正是后续引入统计方法与机器学习方法的出发点：那类方法不再依赖人工枚举关键词，而是从大量已标注的文本中自动学习「什么样的表达通常对应什么样的情感」。本页的规则法示例因此有双重作用——它既是马上可用的打标签工具，也是理解后续 AI 方法要解决什么问题的最直接对照。

⚠️ 七、易混与边界

  • = 是赋值，== 才是判断相等。x = 5 让名字指向 5，本身不产生真假值；x == 5 才是一个比较表达式。把 == 误写成 = 在 if 条件中是直接的语法错误，常见的报错是 SyntaxError: invalid syntax。
  • and 与 or 返回的是操作数本身，不是布尔值。官方文档写明二者「返回最后被求值的操作数」。例如 "" or "未署名" 得到字符串 "未署名"，"标题" and "导语" 得到字符串 "导语"。只有在条件位置被使用时，它们才被解读为真假。要确保拿到布尔值，应显式套一层 bool()。而 not 是例外，它总是返回布尔值。
  • not a == b 等价于 not (a == b)。官方文档的备注指出，not 的优先级低于非布尔运算符，因此 not a == b 被解释为 not (a == b)；而 a == not b 则是语法错误。同样地，在所有运算符中，比较运算的优先级低于任何算术、移位或位运算。
  • 空字符串为假，'False' 却为真。假值的判定依据是「数值为零」或「容器为空」，与字面内容无关。'' 是空字符串，为假；'False' 与 '0' 都是非空字符串，为真；[0] 是含一个元素的非空列表，同样为真。从文件读到的字符串如果内容是 "0"，在条件里会走「真」分支，需要先转成数字再判断。
  • == 比较值，is 比较是不是同一个对象。官方文档说明 is 检测的是标识号。None 与 NotImplemented 是单例对象，PEP 8 建议单例比较总是通过 is 或 is not，绝不要用等于运算符。字符串与整数这类不可变对象的比较，通常应使用 ==。
  • 缩进错误不会被当成「格式问题」轻轻放过。官方教程说明「同一块语句的每一行的缩进相同」，缩进不一致会直接触发 IndentationError。官方编码风格建议是每层缩进用 4 个空格而非制表符，因为混用制表符与空格会产生难以肉眼分辨的对齐问题。

✅ 核查说明：本节六条均以 Python 官方文档为依据。and / or 返回操作数、not a == b 的优先级、is 与 == 的区别、假值清单，见《表达式》6.10 至 6.11 节与《内置类型》真值检测一节；if / elif / else 的结构与缩进要求，见官方教程《4. 更多控制流工具》4.1 节与 4.10 节；单例比较用 is 的建议见 PEP 8。第六节关于规则法局限的讨论属于辅助说明，非官方结论。
