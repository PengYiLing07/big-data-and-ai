🧭 一、学习目标

  • 能说清「Skill」是什么，以及它和普通「提示词 / Prompt」的区别。
  • 能描述一个 Skill 的目录结构与核心文件 SKILL.md 的组成（frontmatter + 正文）。
  • 能理解「渐进式披露（Progressive Disclosure）」如何让装很多技能却不占上下文。
  • 能区分「个人技能」与「项目级技能」的存放位置，并懂得安全使用第三方 Skill。

❓ 二、核心问题

  • 它解决 Agent 的什么问题（为什么不能只靠反复贴提示词）？
  • SKILL.md 长什么样，必填的元数据是什么？
  • 装了 100 个技能为何上下文不被挤爆？
  • 个人 vs 项目级技能各放哪？安全上要注意什么？

📖 三、概念的个人解释

Skill（技能） 是打包给智能体的一份「专业领域说明书 + 工具 + 参考资料」的文件夹， 让一个通用 Agent 在遇到相关任务时能立刻调用这套专长，而不必每次都把冗长步骤重新讲一遍。 官方把它比作「给新同事做的入职引导手册」：不是每次都口头交代，而是把该怎么做、有什么规范、调哪些脚本都写进一沓资料里，需要时翻出来照着做。

关键点在于它是按需加载的：平时只占用很小空间（名字+一句简介），只有当任务相关时才真正把详细内容读进来。这正是它和「把长提示词贴在每次对话里」最大的不同。

💡 我的类比 把 Agent 想成一位全能新员工。你给他装技能，就像在他工位上放好一摞《岗位手册》： 每本封面上只写「这本讲什么、什么时候用」（很小，随时能扫到）。当他接到「帮我处理一份 PDF」的活时， 才去把《PDF 处理手册》翻开，照着里面的步骤、脚本把事办成。平时他不会把 100 本手册全背下来，而是用到哪本翻哪本—— 这就叫「用的时候才加载」，既不占脑子，又能带很多本。

⚙️ 四、核心机制 / 组成

官方把 Skill 定义为一个目录，入口是 SKILL.md，可按需附带脚本与参考资料。结构大致如下：

my-skill/ ├── SKILL.md # 必需：说明书 + 元数据 ├── reference.md # 可选：需要时才读的详细参考 ├── scripts/ │ └── tool.py # 可选：Agent 可直接执行的脚本（不占上下文） └── assets/ # 可选：模板、样例等素材

SKILL.md 顶部是 YAML frontmatter，必填 name 和 description；正文是给 Agent 的说明与步骤。

--- name: concept-learner description: 通用概念学习引擎，接收任意概念并生成可核查的学习资料。用户说“学一下 X/帮我搞懂 X”时触发。 --- # 使用步骤 ...

官方描述的「渐进式披露」分为三层，这是 Skill 能装很多却不占脑的关键：

第 1 层 · 元数据（始终加载）
启动时就装入每个技能的 name + description（每个约一百 token 量级）。够小，装几十上百个也不挤。
第 2 层 · 说明正文（被触发才加载）
当你的请求与某个 description 匹配，Agent 才去读那个 SKILL.md 的正文，此时细节才进上下文。
第 3 层 · 资源/代码（用到才读/执行）
reference、模板、脚本等，需要时才访问；脚本通过执行拿到结果而不把代码塞进上下文。

存放位置决定谁能用：个人级放个人技能目录（所有项目可用）；项目级放仓库里的技能目录（随仓库共享给团队成员），正是本作业把概念学习 Skill 放在 .workbuddy/skills/ 的原因。

🚀 五、一个具体应用场景

场景：给通用 Agent 装一个「概念学习」项目级技能（concept-learner）。

  • 你第一次装好后，Agent 只在系统里登记了它的 name 和一句 description，几乎不占上下文。
  • 当你输入「帮我搞懂 Agent 这个概念」时，description 被匹配 → Agent 才去读 SKILL.md 正文，按其中 7 板块的规范产出学习资料。
  • 下次你说「学一下 RAG」「学一下 向量数据库」，同一个技能无缝复用——Skill 沉淀的是「怎么学任意概念」的方法，而不是针对某一个概念的临时答案。
  • 因为是项目级技能，把它提交到 GitHub 后，同仓库的任何人（或未来的你）都能调用同一套方法，学习成果统一落到 learning-materials/。

这个例子正体现了作业设计意图：Skill 让「生成高质量、可核查概念资料」这件事可复用、可沉淀、可共享。

⚠️ 六、易混与边界

  • 易混 1｜Skill ≠ 普通 Prompt：Prompt 是一次性贴进对话的指令；Skill 是「文件系统的目录 + 按需加载」，可包含脚本与资源，且不用每次重复。Prompt 面向单次，Skill 面向可复用能力。
  • 易混 2｜Skill ≠ 模型自带能力：Skill 是「给 Agent 的说明书 + 脚本」，它不改变底层模型参数；它的价值在于把流程知识显式、可复用地喂给 Agent。
  • 边界 1｜必须来自可信来源：第三方 Skill 本质是「让 Agent 执行你给的指令/代码」，恶意的 Skill 可能诱导 Agent 做危险操作或泄露数据。只应使用自己创建或官方发布的技能，外部来源要先审计。
  • 边界 2｜同名/层级有优先级：个人级与项目级技能可能同名，且有覆盖顺序；跨平台/跨工具也有可用范围限制，不能假设处处通用。
✅ 我的核查说明（人工） 核心表述（Skill=含 SKILL.md 的目录、frontmatter 必填 name+description、三级渐进式披露、个人 vs 项目级位置、安全审计）均取自 Anthropic 官方 Agent Skills 文档与官方博客，多处原文一致后我采信。 目录/层级示例中「.workbuddy/skills/」是本课程平台的项目级技能路径，与官方示例路径对应，属平台约定而非官方原话，故单列说明。
